# Home Balance Comparison

## Objective and scope

Show the current account balance in a selected display currency (VES, USD, or EUR), a truthful bolívar equivalent when available, and a comparison against the portfolio balance at the end of the preceding month. The supplied screenshot is a visual reference, not a source of financial amounts or a requirement to include USDT as a display choice. Keep USDT account balances supported.

## Product rules and constraints

- Display currency changes only valuation, never the user's base-currency preference, account membership, ledger amounts, or transaction FX snapshots. Use the canonical exact-decimal and monetary-unit rules. No assumed currency parity or fabricated zero for a missing rate.
- Compare current active-account balances against the balances of accounts that existed at the preceding month-end (including those subsequently archived, where records permit). Treat `Account.createdAt` as an **approximation** of the effective date of the opening balance, explicitly disclose this assumption in the UI. Cut ledger transactions using `Transaction.occurredAt < current-month start` in the user's financial timezone and exclude voided transactions. Do not use monthly cash flow as a substitute for previous net worth.
- Value each period with a dated rate effective at that period's cutoff; do not substitute transaction FX snapshots for portfolio rates, use future rates for historical balances, or mix mismatched quote dates to fabricate USD/EUR crosses. If either period's selected-currency valuation is partial/unavailable, suppress the percentage and disclose missing currencies and rate date/source where known. Zero prior balances must not produce a divide-by-zero percent.
- Reuse the existing owned dashboard projection, timezone, FX and contracts boundaries; preserve current loading/error, partial-FX disclosure, four navigation destinations, and accessible responsive mobile layout. Do not implement bank sync or live exchange-rate ingestion as part of this request; stored usable rates determine availability.
- Preserve the pre-existing dirty `AGENTS.md`, `apps/mobile/package.json`, `apps/mobile/src/features/screens.tsx`, and `pnpm-lock.yaml` edits. In particular, keep the user's Lucide icon changes. No remote operations are authorized.
