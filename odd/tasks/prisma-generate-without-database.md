# Generate Prisma Client without a database URL

## Objective and why
Make the API's Prisma Client generation during `pnpm install --frozen-lockfile` work in CI without `DATABASE_URL`. The current config calls `env('DATABASE_URL')` while loading every Prisma command, so even database-free `prisma generate` fails before generation starts.

## Scope and acceptance
- Only `apps/api/prisma.config.ts`, one focused API regression test, and this task record. No dependency changes, credentials, remote operations, API startup, or live database access.
- With `DATABASE_URL` absent, the real CLI generates the client successfully; a database-dependent read-only command fails promptly with a missing datasource URL rather than connecting. An explicitly provided URL remains available to database commands.
- Run `pnpm --dir apps/api test`, `pnpm --dir apps/api typecheck`, an isolated no-URL `pnpm --dir apps/api exec prisma generate --schema prisma/schema.prisma`, `pnpm gate`, and `git diff --check`. Optional frozen install only after assessing local safety; do not execute database migrations or pushes.
- Prisma ORM and Client 7.10.0 are pinned in `apps/api/package.json` and `pnpm-lock.yaml`. Official v7 Config API: https://www.prisma.io/docs/orm/reference/prisma-config-reference (optional environment variables: `env()` throws on config load; `generate` itself needs no URL). Verify installed types/CLI for the selected optional datasource representation.
