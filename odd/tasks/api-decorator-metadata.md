# API decorator metadata runtime

## Objective
Start the API from TypeScript-emitted JavaScript so Nest constructor injection receives legacy `design:paramtypes` metadata, and make the health smoke harness exercise that same build.

## Problem and why
The API starts through `node --import tsx src/main.ts`, but tsx/esbuild does not support `emitDecoratorMetadata`. The observed `HealthController` metadata is missing despite `PrismaService` being registered; the observed health response was HTTP 500 with an undefined injected service. The smoke harness compiles with `noEmit: true` and then attempts to launch output that cannot exist.

## Scope and constraints
- Authorized: API build/start scripts, TypeScript emit configuration, focused metadata regression and existing smoke harness, plus ignore rules for generated output. No dependencies, user account requests, database data queries, live port 3000 changes, or unrelated feature documents.
- Preserve existing CORS and error logging. Inspect any pre-existing generated output before replacing or cleaning it; never delete user-owned files. Generated output must remain untracked.
- Technology: pinned TypeScript 7.0.2, NestJS 12.0.1, tsx 4.23.12, Node 24.20.0 and pnpm 11.24.0. Official tsx documentation states metadata emission is unsupported; TypeScript legacy decorator emit is required.
- TDD: standard (strict TDD not affirmatively enabled in the known project testing context); runner `pnpm --dir apps/api test`, plus `typecheck`, isolated emitted-JS metadata check, and `smoke` only when a local database, free port 3217, and safe cleanup are confirmed.
- Delivery: `ask-on-risk` by default; authored changed-line estimate 90–160 for this single work unit, including this document and regression. The ~400-line review threshold is advisory, not a code-golf target. No staging, commit, push, remote access, or SDD artifacts by this writer.
